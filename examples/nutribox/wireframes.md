# Wireframes: LunchBox — подписка на здоровые обеды для офисов · Платформа: Desktop (веб, 1200px+)

> [assumption] Выбрана Desktop-веб-платформа: оформление и управление подпиской в MVP идут только через веб (US-001 Notes), продукт — B2B-инструмент для офис-менеджера и бухгалтерии. Экран сотрудника (выбор блюда) спроектирован адаптивно и одинаково работает в вебе на десктопе; мобильная версия едока — вне MVP.

## Экран: 1. Мастер оформления подписки
**Контекст:** офис-менеджер зашёл на сайт и решил подключить питание команды · **Цель:** оформить подписку под ключ менее чем за 10 минут · **Покрывает:** US-001, US-002, SS-001

### Аннотации
| # | Элемент | Поведение |
|---|---|---|
| 1 | Прогресс-степпер (3 шага) | Показывает пройденные/текущий шаг; клик по пройденному шагу возвращает к нему без потери данных. Держит весь мастер в ≤3 экранах (AC US-001). |
| 2 | Поле «Число сотрудников» | Фиксирует размер команды; уходит в параметры офиса (SS-001) для планирования. |
| 3 | Поле «Обедов в день» | Согласованное число обедов; если меньше числа сотрудников — инлайн-подсказка ⚠, ошибкой не блокирует. |
| 4 | Обеденное окно (от–до) | Диапазон доставки; влияет на логистику (SS-001, US-008). |
| 5 | Ссылка на реквизиты (шаг 1) | Реквизиты юрлица и контакт бухгалтерии редактируемы до счёта (US-002). |
| 6 | Primary «Продолжить» | Валидирует шаг и ведёт к «Проверка» → подтверждению; после финиша фиксирует подписку в план производства/логистики (SS-001). |

### Состояния
- **Empty:** первый вход — поля пустые, реквизиты подтягиваются с шага 1; кнопка «Продолжить» неактивна, пока не заполнены обязательные поля. · **Loading:** при отправке подписки — спиннер на кнопке, поля заблокированы. · **Error:** невалидные реквизиты/адрес — инлайн-ошибка под полем; сбой сохранения — баннер «Не удалось сохранить, попробуйте ещё раз» с повтором.

### Переходы
- «Продолжить» (валидно) → Шаг 3 «Проверка и подтверждение» → экран статуса подписки (дата старта, AC US-001).
- «Назад» → Шаг 1 «Реквизиты».
- После подтверждения → Экран 2 «Настройка офиса» (CTA «Пригласить сотрудников»).

### Переходы
- «Отправить приглашения» → строки со статусом «приглашён · ожидание» в таблице (5).
- Клик сотрудника по ссылке (вне экрана менеджера) → онбординг едока → указание ограничений (US-004) → Экран 3.
- «Напомнить всем» → повторная рассылка неподключённым.
- Верхняя навигация «⌂ Обзор» → Экран 4 «Дашборд менеджера».

## Экран: 3. Выбор блюда сотрудником
**Контекст:** сотрудник открыл меню на сегодня/неделю до дедлайна выбора · **Цель:** выбрать подходящий обед менее чем за минуту, доверяя составу · **Покрывает:** US-004, US-005, US-006, US-007, SS-002

### Wireframe
```
╭──────────────────────────────────────────────────────────────────────╮
│  LunchBox · Меню            Пн 04.08   ◀ Сегодня ▶      Максим ◯       │
├──────────────────────────────────────────────────────────────────────┤
│  ⚠ Дедлайн выбора на сегодня: до 10:30 (осталось 1 ч 12 мин)   ← 1     │
│  Ваши ограничения: вегетарианское ✓ · без орехов        [ Изменить ]←2 │
│                                                                        │
│  ╭─────────────────────────╮   ╭─────────────────────────╮            │
│  │ Боул с киноа и овощами  │   │ Паста с грибами         │     ← 3     │
│  │ ─────────────────────── │   │ ─────────────────────── │            │
│  │ 520 ккал · Б22 Ж18 У60  │   │ 610 ккал · Б19 Ж24 У72  │  ← 4       │
│  │ Аллергены: глютен       │   │ Аллергены: глютен, соя  │  ← 5       │
│  │ Вегетарианское ✓        │   │ Вегетарианское ✓        │            │
│  │ ★★★★☆ 4.3               │   │ ★★★★★ 4.7               │            │
│  │ ╭─────────────────────╮ │   │ ╭─────────────────────╮ │            │
│  │ │   Выбрать этот  ●   │ │   │ │   Выбрать этот  ○   │ │  ← 6       │
│  │ ╰─────────────────────╯ │   │ ╰─────────────────────╯ │            │
│  ╰─────────────────────────╯   ╰─────────────────────────╯            │
│                                                                        │
│  [ ✓ Выбрано: Боул с киноа ]                                    ← 7    │
│  ────────────────────────────────────────────────────────────────     │
│  Меня не будет — пропустить обед:                                      │
│  [ ] Сегодня   [ ] Отметить дни недели ▼               ← 8            │

│    меню дня. [assumption]                                     ← 9     │
╰──────────────────────────────────────────────────────────────────────╯
```

### Аннотации
| # | Элемент | Поведение |
|---|---|---|
| 1 | Таймер дедлайна | Показывает крайний срок выбора на день и остаток времени (AC US-005/US-007); после дедлайна выбор блокируется. |
| 2 | Плашка ограничений + «Изменить» | Отражает пищевые ограничения едока; меню (3) уже отфильтровано по ним автоматически (US-004). |
| 3 | Карточки блюд (день/неделя) | Список доступных блюд с учётом ограничений; переключатель дат сверху даёт выбор на неделю (US-005). Цель — выбор < 1 мин. |
| 4 | Состав/КБЖУ | Калорийность и БЖУ каждого блюда видны до подтверждения (US-006). |
| 5 | Строка аллергенов | Явный список аллергенов на карточке — критично для здоровья (US-006, риск маркировки). |
| 6 | Radio «Выбрать этот» (○/●) | Одиночный выбор блюда на дату; мгновенно фиксирует выбор, подсвечивает выбранную карточку. |
| 7 | Индикатор «Выбрано» | Подтверждает текущий выбор; выбор уходит в сводный заказ офиса к дедлайну (SS-002). |
| 8 | Чекбоксы пропуска | Отметка «пропустить сегодня» или на выбранные дни недели (US-007); пропуски идут в отчёт потребления (US-011). |
| 9 | Подсказка про дефолт | Объясняет поведение при отсутствии выбора — блюдо по умолчанию [assumption] (US-005, SS-002). |

### Состояния
- **Empty:** меню на дату ещё не опубликовано — плейсхолдер «Меню появится позже» и неактивные карточки. · **Loading:** загрузка меню/применение фильтра ограничений — скелетоны карточек. · **Error:** сбой сохранения выбора — тост «Выбор не сохранён, повторите»; после дедлайна — блокирующий баннер «Время выбора истекло, будет блюдо по умолчанию».

### Переходы
- «Выбрать этот» (●) → фиксирует выбор → строка «Выбрано» (7); выбор агрегируется в сводный заказ офиса к дедлайну (SS-002).
- «Отметить дни недели» ▼ → дропдаун выбора дней пропуска.
- ◀ / ▶ по датам → меню другого дня (режим «на неделю»).
- После дня доставки → карточка блюда получает CTA «Оценить» (1–5) → данные в дашборд (US-010).

| 5 | Предварительный счёт | Сумма за период по модели подписки (SS-004, фикс за место [assumption]); прозрачный расчёт до выставления. |
| 6 | Строка документооборота | Показывает, что единый счёт и акт уйдут на контакт бухгалтерии автоматически (US-009). |
| 7 | «Отчёт потребления ↓» / «Реквизиты» | Скачивание детального отчёта по потреблению (SS-004); правка реквизитов бухгалтерии до счёта (US-002). |
| 8 | Блок ротации | Список низкорейтинговых блюд, помеченных к ротации на основе агрегированных оценок (SS-005, US-010). |

### Состояния
- **Empty:** первый месяц без данных — метрики показывают «нет данных за период», лента доставок пуста до первого дня. · **Loading:** пересчёт при смене периода/офиса — скелетоны карточек метрик и таблиц. · **Error:** сбой формирования отчёта/счёта — баннер «Не удалось рассчитать, данные могут быть неполными» с повтором; недоставленная закрывашка — метка «Документы не отправлены» с действием «Отправить повторно».

### Переходы
- «Отчёт потребления ↓» → выгрузка файла отчёта за период (SS-004, US-011).
- «Подробнее» (задержка) → карточка инцидента доставки.
- «Реквизиты бухгалтерии» → форма редактирования реквизитов (US-002, до выставления счёта).
- Смена периода в селекторе (1) → пересчёт всех метрик, доставок и предварительного счёта.
- «◯ Сотрудники» в навигации → Экран 2 «Настройка офиса» (статусы, приглашения).
